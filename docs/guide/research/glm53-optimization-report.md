# Getting the best performance out of GLM-5.3 and GLM-5.3-Flash (Z.ai) as coding and agentic models

**Date:** 2026-11-18. **As-of:** every web source below was fetched live on 2026-11-18; GitHub repo freshness uses `pushed_at` from the GitHub API on that date. Publication dates are given where the page states them.

**Sparseness note (required by dispatch):** GLM-5.3 shipped 2026-08-14 and GLM-5.3-Flash 2026-08-26 [S4][S5], so the model is three months old at research time. This turned out not to be sparse territory: Z.ai's docs site, the GLM-5 GitHub repo and its issue tracker, Artificial Analysis, and several independent engineering writeups all carry 5.3-specific material, and no claim below is padded from pre-5.3 memory. What is genuinely thin: a public requests-per-minute/TPM rate-limit table (login-walled) and any official Z.ai "prompting guide" document. No such guide exists as of today; my own crawl of the full docs surface (via the site's llms.txt index) confirms Z.ai distributes its prompting advice across capability pages rather than one guide.

**Question as dispatched:** how to actually get the best performance out of GLM-5.3 and GLM-5.3-Flash as coding and agentic models: official guidance, practitioner quirks, routing advice, GLM-lineage prompting continuity, ecosystem repos, and plan-tier mechanics.

## The ten things a power user should change today

1. **Set `reasoning_effort` explicitly on every request.** Thinking is forced on in GLM-5.3 and GLM-5.3-Flash; `thinking.type: "disabled"` errors on 5.3 and any unrecognized `reasoning_effort` value silently falls back to `max`, the default [S1][S7][S23][S32]. The three real levels are `low`, `high`, `max` [S7]. Z.ai recommends `max` for coding and for benchmark reproduction [S1][S7][S23]; `low` is your only real throttle on thinking-token spend. On the Coding Plan, harness values remap: `none`/`minimal`/`low` to `low`, `medium`/`high` to `high`, `xhigh`/`max`/`ultra` to `max` [S7][S20].
2. **Do not drop reasoning content from agent turns.** Preserved thinking (`clear_thinking: false`) is the agent-mode default on the Coding Plan endpoint and in the 5.3 chat template; returning prior reasoning blocks byte-identical and in original order preserves reasoning continuity, raises cache hit rates, and saves tokens. Editing or reordering them hurts both performance and caching [S6][S23]. For plain chat (non-agent) use, pass `clear_thinking: true` explicitly [S23][S25].
3. **Engineer for the cache before anything else.** Caching is implicit and automatic; cached input bills at $0.26/M vs $1.40/M on GLM-5.3 and $0.03/M vs $0.15/M on Flash (roughly a fifth of input price, an 80-81% discount) [S17][S30][S31]. On the plan, cached-input credit multipliers are 1.7 vs 6.9 (5.3) and 0.56 vs 2.3 (Flash) [S3]. Hit-rate mechanics: byte-identical stable system prompts, long reference documents in the system message, append-only conversation ordering; minor formatting differences degrade hits [S9]. Z.ai claims 98%+ hit rates in ZCode yield about 30% more effective tokens (vendor claim) [S4].
4. **Move heavy batch work out of peak hours.** Peak is weekdays 14:00-18:00 Singapore time (UTC+8); everything else, including all weekend, is off-peak at 50% of standard points [S3][S4][S15]. The credits revision notice frames the same economics as GLM-5.3 at 1x off-peak vs 3x peak and Flash at 0.4x off-peak vs 1.2x peak [S15]; either way, a max-effort GLM-5.3 run costs roughly a third off-peak what it costs at peak.
5. **Route Flash for breadth and GLM-5.3 for judgment, and make Flash's quota arithmetic work for you.** Flash carries 3x the Coding Plan quota of GLM-5.3 (multipliers 2.3/0.56/8 vs 6.9/1.7/24 per 10k tokens) [S2][S3], beats GLM-5.2 on six coding/agentic benchmarks per Z.ai (DeepSWE 63.4 vs 46.2; vendor-reported) [S2][S5], and on the independent Featherbench set scored 99% at $0.0004/task vs GLM-5.3's 100% at $0.0101/task [S35]. Artificial Analysis prices the gap as Intelligence Index 28 vs 32 and $0.58 vs $5.01 per index task [S30][S31]. Z.ai's own plan routing sends GLM-4.7 requests to Flash [S3]. Keep `max`-effort GLM-5.3 for load-bearing judgment: a field report shows Flash at `low` effort falsely certifying a defect it missed and composing a final answer that contradicted its own correct deliberation, clean at `max` [S24, issue #170].
6. **Wire Claude Code (and siblings) to the right endpoint with a long timeout.** `ANTHROPIC_BASE_URL=https://api.z.ai/api/anthropic`, `ANTHROPIC_AUTH_TOKEN=<z.ai key>`, `API_TIMEOUT_MS=3000000`; other OpenAI-compatible tools use `https://api.z.ai/api/coding/paas/v4`, Codex uses `https://api.z.ai/api/v1` [S14][S16][S20][S21]. A 50-minute timeout is the documented default for a reason: max-effort long-horizon runs are slow (median time-to-first-token 68.47s at max effort on GLM-5.3; 86.84s on Flash, Artificial Analysis measurements) [S30][S31]. The `[1m]` suffix on a model name requests 1M context in Claude Code (`glm-5.3-flash[1m]`); `/effort` sets effort in-session [S20]. Wrong endpoint selection is the documented cause of "1113 Insufficient Balance" surprises and silent balance billing [S14].
7. **Flatten tool schemas and keep `tool_choice: "auto"`.** `tool_choice` supports only `auto` [S8]; a minimal A/B on the Coding Plan endpoint shows glm-5.3 returns empty arguments `{}` whenever a tool's schema puts all fields inside `oneOf` branches under empty top-level `properties`, while the flat equivalent returns correct arguments (open bug, 2026-10-15) [S24, issue #169]. On the Anthropic-compatible Messages API, `tool_choice: {"type": "none"}` is ignored; strip `tools` from the request instead [S32]. Parallel tool calls are declared supported (verified two parallel calls on Responses) with an upstream cap around 128 functions [S32].
8. **Leave sampling near defaults and tune one knob at most.** Defaults for 5.3: `temperature: 1.0`, `top_p: 0.95`, `do_sample: true` [S18][S19]. Z.ai's own benchmark runs use temperature 1.0 with top_p 0.95 or 1.0 (DeepSWE used 0.95) [S4]. Valid ranges are narrow (temperature [0,1], top_p [0.01,1]) and out-of-range values are silently accepted on Chat Completions/Responses; only Messages rejects them [S32]. The migration guide's advice: adjust temperature or top_p, never both [S18].
9. **Pin the output language in the system prompt and restart sessions on drift.** GLM-5.x has a documented tendency to emit Chinese mid-English agentic sessions: open issue #142 on GLM-5.3-Flash (survives full context reset, so it is not a caching artifact), its escalation #163, the closed GLM-5.1 twin #54, and a GLM-5.2 Cursor-community thread reporting the same behavior [S24][S42]. Long multi-turn tool sessions are the trigger context; the working mitigations are an explicit "always respond in English" rule in the system prompt and a fresh session when drift appears [S24][S42].
10. **Budget in the credit formula, not in vibes.** Plan credits = (input x input multiplier + cached input x cached multiplier + output x output multiplier) / 10,000, with output dominating (24 vs 6.9 for GLM-5.3) [S3]. Thinking tokens are output tokens, so `max` effort is the expensive axis; reasoning grew 27 to 39 tokens on a trivial arithmetic prompt from `low` to `max` in one verified test [S32], and multi-hour max-effort loops are where accounts bleed (a practitioner burned 450M tokens/$150 on one mis-routed MCP prototype overnight) [S33]. Cap `max_tokens` deliberately (default 65536, hard ceiling 131072 enforced) [S19][S32].

## Q1. Official surface: Z.ai docs, blog, and plan guidance

**Model facts.** GLM-5.3: text-only, 1M-token context, 128K max output (the API enforces `max_tokens` ceiling 131072), `glm-5.3` model ID, same base model as GLM-5.2 with all gains from post-training; 744B total / 40B active parameters per the GLM-5 repo (Artificial Analysis independently measures 753B) [S1][S23][S30]. GLM-5.3-Flash: natively multimodal (image, video, file in; text out), 1M context, 128K output, 320B total / 18B active, a newly trained base with hybrid sparse+linear attention, IndexPool compression, and Manifold-Constrained Hyper-Connections; Z.ai claims 3.01x less attention compute and 4.44x smaller KV cache vs GLM-5.3 [S2][S23]. One docs inconsistency to know: the Flash docs page compares its size against "355B / 32B," which is the GLM-4.5 architecture, not GLM-5.3's 744B/40B; the GitHub/Hugging Face cards are the architecture source of record [S2][S23][S25]. Model IDs include `glm-5.3-flash` and the faster `glm-5.3-flashx` (about 200 tokens/s, API-only, not on the plan as of the docs page) [S2][S17]. OpenRouter also lists a `z-ai/glm-5.3-prime` high-speed GLM-5.3 variant claiming 1.5-2x output throughput [S40].

**Thinking controls.** Forced thinking; `reasoning_effort` low/high/max, default max, recommended max for coding; `thinking.type: "disabled"` fails on 5.3/Flash (migration path: switch to `enabled` plus `reasoning_effort: "low"` before changing the model ID, or the request errors) [S1][S4][S7][S18]. Higher effort raises latency and thinking-token consumption; the docs recommend streaming so reasoning is visible [S7]. GLM-5.2 accepts a seven-value effort vocabulary remapped onto the same three levels; 5.3 tightens to three [S7][S23]. The Claude Code plan integration exposes this as an `/effort` command with its own conversion table, priority explicit effort > thinking toggle > default max [S20].

**Sampling.** Defaults temperature 1.0, top_p 0.95; tune at most one [S18][S19]. Official benchmark configs corroborate temperature 1.0 across harnesses (Terminal-Bench 3.0, ALE, CyberGym, PostTrainBench all at temperature 1.0, top_p 0.95-1.0, max effort, in the Claude Code 2.1.207 harness) [S4].

**System prompt.** There is no dedicated official prompting guide. The docs' own coding examples use a persona-style system prompt ("senior full-stack software engineer") [S1]. The server-side prompt injected on the pay-as-you-go API is minimal (identity line, current date, content boundaries; no hidden formatting or tooling rules), so your system prompt carries all structure [S37]. The plan's best-practice page recommends task prompts built as Goal, Context, Constraints, and an explicit "Done when" completion criterion; plan-then-implement for complex work; rules moved from prompts into project config; one session per task; periodic context compression; and sub-agent delegation for exploration and test-running [S11]. The memory-mechanism page adds: keep the main memory file under about 200 lines, split rules into topical files loaded only when relevant, write specific verifiable rules ("run pnpm test after changing business logic") over abstractions, and persist long-term rules to disk because conversation-only rules die at compaction [S12].

**Tool calling.** OpenAI-style `tools` array; `tool_choice` supports only `auto`; echo `tool_call.id` back in the tool result; provide detailed descriptions with `enum`, `default`, `examples` in schemas; single responsibility per function [S8]. `tool_stream: true` (new, off by default) streams tool-call arguments incrementally; concatenate fragments by `tool_call.index` [S18]. Flash docs recommend enabling both `stream` and `tool_stream` for streaming tool use [S2].

**Context window and caching.** 1M context on both models [S1][S2]. Caching is implicit, no parameters; hits visible at `usage.prompt_tokens_details.cached_tokens` [S9][S32]. The cache page still says cache hits bill at "usually 50%" of standard price, while the concrete pricing page and the plan multipliers both put cached input at roughly 19-20% of input price; the specific numbers win, and the 50% sentence reads as legacy text [S9][S17][S3]. Hit-rate discipline: identical byte-stable system prompts, long documents placed in the system message, consistent append-only history ordering; formatting differences and content changes degrade hits; no public TTL [S9]. The GLM-5.3 blog's ZCode section credits cache discipline plus a then-promotional quota boost for "up to 180% your standard quota" (marketing framing, promo window ended August 31) [S4].

**Structured output.** `response_format: {"type": "json_object"}`; there is no `json_schema` strict mode upstream, so the documented pattern is schema-in-system-prompt plus client-side validation (jsonschema), ISO 8601 dates, omit-unknown-fields over guessing, and a simplified fallback schema for robustness [S10][S32].

**Agent-mode specifics.** ZCode (Z.ai's own harness) is the reference agent surface: Goal mode (plan, code, test, verify until target met), Remote Control steering via phone, and the cache-hit claims above [S4]. ZCode's open-source CLI documents the eval-side mechanics: per-sample isolated home/workdir/data-dir, `--workflow-mode`, `ZCODE_MAX_TOOL_CONCURRENCY`, model configuration via `~/.zcode/v2/provider_config.json` supporting openai-chat-completions, openai-responses, and anthropic-messages protocols [S27].

## Q2. Quirks and failure modes practitioners report

- **Thinking cannot be turned off, and misconfigurations fail soft.** `disabled` is auto-converted rather than rejected on some routes (HTTP 200 with reasoning still returned) [S32]; invalid `reasoning_effort` values silently become `max` [S23][S32]. Silent fallback cuts both ways: you think you set `low` and you are paying for `max`.
- **Low effort degrades verification honesty.** Field report (open issue #170): Flash at `low` effort affirmatively certified a missed QC defect and, in a second brief, computed correct row-level numbers in deliberation then emitted a new arithmetic error in the composed answer; identical briefs were clean at `max`. The reporter's lesson: a signed-off error is worse than a miss because downstream steps chain on QC output [S24].
- **Tool-schema shape can silently empty your arguments.** Issue #169: schemas with empty top-level `properties` plus `oneOf` branches produce stable `{}` arguments on both 5.3 and Flash via the plan endpoint; the flat-schema variant of the same tool works. Open as of 2026-10-15 [S24].
- **`tool_choice: none` is ignored on the Messages API.** The model keeps issuing tool calls; remove `tools` entirely. Chat Completions honors string `"none"` [S32].
- **Chinese-token bleed in long English agent sessions.** Issue #142 (Flash, open): inline CJK tokens and full Chinese sentences in otherwise-English output, four events across two sessions, one in a fresh session seven minutes after a full reset, ruling out context contamination. Escalation #163 reports full multilingual garbage collapse. The GLM-5.1 twin (#54, closed) and a Cursor-community GLM-5.2 thread match the pattern [S24][S42]. Working mitigation: an explicit always-respond-in-English system rule plus session restarts [S42].
- **Circular reasoning and empty outputs under load.** Practitioners on the Flash HN thread (pre-release "ox-alpha" period) reported looping thinking and occasional no-output completions, partly congestion, partly model behavior [S38]. Artificial Analysis independently tags Flash "somewhat verbose" and slow per task (39.1 min per Intelligence Index task, rank 28/29 in class) [S31].
- **Provider capacity is a real failure axis for open-weight models.** The one-month Flash practitioner had to switch providers mid-month for performance degradation; his MCP prototype also burned 450M tokens overnight on the wrong model choice [S33].
- **Self-hosting sharp edges.** The Flash chat template crashes on OpenAI-spec string `tool_calls[].function.arguments` (issue #158, local serving) [S24]; vLLM/SGLang need the `glm47` tool-call parser and `glm45`/`glm47` reasoning parser, and GLM-4.x-lineage local serving passes explicit stop tokens `<|user|>`, `<|endoftext|>`, `<|observation|>`, `<|assistant|>` [S23][S41].
- **Cross-tenant cache leakage happened in the wild.** Cloudflare's GLM-5.3 Workers AI deployment leaked other customers' prompt text in 155 responses (2026-08-27 to 09-09): a KV-pool smaller than the advertised context plus an SGLang disaggregated-prefill bug returned 200s built on stale cache pages. Lessons if you self-host or pick a host: KV pool must exceed context length, rejected requests must die before KV transfer (fixed in SGLang v0.5.22+), and test output coherence, not just status codes [S34].
- **Plan endpoints reject JSON-RPC batches.** Issue #175: the plan's MCP endpoints (web_search_prime / web_reader / zread) return raw HTTP 400 to batched JSON-RPC, breaking Codex CLI and other batching clients [S24].
- **Minimal server-side prompt.** The PAYG API injects only identity, date, and content boundaries; the model "frequently hallucinates that it's Claude" when asked, which matters if your agent logic keys on model identity [S37].

## Q3. Routing: Flash-class vs the strong tier

**Z.ai's positioning (vendor, label as marketing where marked).** Flash is priced for volume: 3x plan quota [S2][S3], off-peak 0.4x vs GLM-5.3's 1x [S15]. Z.ai reports Flash outperforming GLM-5.2 on six coding/agentic benchmarks including DeepSWE 63.4 vs 46.2 (vendor-reported) and approaching Claude Opus 4.8 on Z.ai's internal code bench at max effort, 29.0 vs 29.5 (vendor-reported, internal benchmark) [S2][S5]. FlashX targets latency (about 200 tokens/s, vendor-reported) [S2][S17].

**Independent numbers.** Artificial Analysis: GLM-5.3 Intelligence Index 32 at max effort (23 at low), 87 tok/s output, 68.47s median TTFT, $5.01 per index task (rank 30/30 on cost-efficiency among 30 peers, i.e., expensive per unit of intelligence); Flash II 28, 57 tok/s, 86.84s TTFT, $0.58 per task, blended $0.10/M [S30][S31]. Featherbench (28 everyday tasks, single trial): GLM-5.3 100% pass at $0.0101/task; Flash 99% at $0.0004/task, 2.6s TTFT (through OpenRouter routing) [S35]. An independent review checking the public DeepSWE leaderboard found GLM-5.3 max at 69% ±3% vs GLM-5.2 max 44% ±2% at nearly identical per-rollout cost, concluding the 5.3 gain is resolution rate, not token efficiency, and that gains are coding-targeted rather than universal (Vending-Bench 2 ranges overlap) [S36].

**Practitioner routing verdicts.** One month of daily Wagtail core development on Flash alone: "really polyvalent," viable for everyday work, with vision plus 1M context as the differentiators; the author's October adjustment was multi-agent splits (orchestrator, scout, implementer, reviewer with bounded goals) rather than model escalation [S33]. HN practitioners treat the Flash tier as price/performance pressure on routine tasks while keeping frontier tiers for the hardest work [S38]. The concrete routing rule the evidence supports: Flash at `high`/`max` for broad implementation, search, summarization, and visual tasks; GLM-5.3 at `max` for architecture, tricky debugging, security review, and anything whose wrong output chains downstream (see issue #170); Flash at `low` only for genuinely trivial turns. Z.ai's own harness ZCode orchestrates both models and the plan auto-routes GLM-4.7-named requests to Flash [S3][S4].

**Self-hosting throughput reference.** NVIDIA's November serving post runs GLM-5.3 NVFP4 on two GB300s (TP=2) with vLLM 0.30.0, MTP speculative decoding (4 tokens), fp8 KV cache, prefix caching: 107.4 tok/s single-stream, 607.8 tok/s aggregate at concurrency 16, degrading past that; the post's tuning lessons (match `--max-num-seqs` to target concurrency, change one flag at a time) apply to any GLM-5.3 self-host [S39].

## Q4. GLM-lineage prompting continuity (4.x to 5.x), labeled

- **Interleaved + preserved thinking are lineage behaviors that 5.3 hard-codes.** Introduced through GLM-4.5/4.6/4.7 (interleaved thinking between tool calls; preserved thinking for coding agents; turn-level thinking toggles from 4.7), the 5.x line makes thinking mandatory and drops the off switch [S6][S23][S41]. Inference for 5.3: treat "think about which turns need deep thought" as obsolete; control depth only via `reasoning_effort` (verified present), not via mode toggles.
- **Structured output discipline is unchanged.** JSON mode via `response_format`, schema embedded in the system message, client-side validation, start simple then add complexity: the current docs carry the 4.x-era pattern forward verbatim in substance [S10].
- **Tool-call parser and stop-token mechanics (local serving, lineage-legacy).** GLM-4.x serving used `glm45`/`glm47` parsers and explicit stop tokens; the GLM-5 repo and NVIDIA's post still specify `glm47` tool parsing for 5.3-family serving, so parser identity carries forward (verified for serving configs) while the stop-token list is documented only in the 4.6 TIR guide and is inferred, not verified, for 5.3 [S23][S39][S41].
- **Language-mixing is a lineage bug, not folklore.** Reproduced across 5.1 (#54, closed), 5.2 (community report), and 5.3-Flash (#142, #163, open) [S24][S42]; bilingual training (en/zh) is stated on the model card [S25]. The 4.x-era fix (explicit language directive, mirror the conversation's language) still works; inferred continuity, consistent with reports.
- **XML/markdown section discipline.** Neither Z.ai's 5.3 docs nor the model cards prescribe XML tags or specific markdown scaffolding; official examples use plain structured markdown with clear sections. Any stronger claim about format tags would be invention. What the docs do prescribe is stability: formatting differences alone degrade cache hits, so pick one structure and keep it byte-stable [S9].
- **Sampling continuity.** temperature 1.0 as the documented default and eval standard traces from 4.x guidance through 5.3 docs [S1][S18][S41].

## Q6. Plan-tier mechanics for heavy CLI users

- **Credits, not tokens.** Both a 5-hour rolling quota and a weekly quota: Lite 2,000/10,000, Pro 12,000/60,000, Max 28,000/140,000 credits; 5-hour credits reset 5 hours after consumption, weekly resets every 7 days from order time [S3][S14]. Formula: (input x 6.9 + cached x 1.7 + output x 24)/10,000 for GLM-5.3; (input x 2.3 + cached x 0.56 + output x 8)/10,000 for Flash; MCP tool calls bill 1.2 x output multiplier per call [S3]. With a high cache-hit rate, Z.ai's worked examples stretch a Lite weekly quota to 48M-104M GLM-5.3 tokens (vendor examples) [S3].
- **Off-peak.** Peak: weekdays 14:00-18:00 UTC+8. Everything else half-price credits, weekends all day [S3][S15]. One framing note: the overview page says off-peak consumes 50% of standard points, while the July 30 revision notice expresses the same system as 1x/3x (GLM-5.3) and 0.4x/1.2x (Flash) peak/off-peak multipliers; the ratio (peak costs 3x off-peak for 5.3, 3x for Flash) is consistent, but reconcile against your own dashboard before scripting schedules [S3][S15].
- **No balance fallback.** Depleted plan quota just waits for the next window; the system will not dip into pay-as-you-go balance, and using plan keys outside supported tools or endpoints produces the 1113 error or silent balance billing [S14]. Plan keys, team keys, and standard API keys are separate and non-interchangeable [S16].
- **Concurrency is tiered and dynamic.** Documented guidance: Lite one project at a time, Pro 1-2, Max 2 or more, with higher off-peak ceilings; parallel calls via subagents are explicitly allowed; account sharing is prohibited and three violations risk a ban [S13]. There is no public RPM/TPM table; the rate-limits doc redirects to a login-walled console page.
- **Effort affects quota through output tokens.** Reasoning is billed as output; `low` vs `max` is the only in-flight lever (thinking cannot be disabled), plus routing to Flash (0.4x off-peak multiplier and 3x quota headroom) [S1][S3][S15][S32].
- **Promotions and edges.** The tools page lists ZCode and AutoClaw with a "1.5x usage" line item; the 5.3 blog framed the same number as a limited-time quota boost through August 31, so treat current multipliers as checkable, not permanent [S4][S22]. Quota Reset Cards exist as campaign benefits [S14]. Team plans bill per-seat in tokens instead (standard seat: 60M/300M weekly GLM-5.3; premium 160M/800M) [S15]. Legacy plan holders keep old terms until cycle end [S15].
